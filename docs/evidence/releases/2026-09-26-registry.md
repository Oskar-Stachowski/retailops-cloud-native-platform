## Verified behavior

The workflow built the previous `0.2.0` source (`cb0c79848247`) and candidate
`0.2.1` source once, then tested update, API outage and rollback. All four exact
images passed the Trivy 0.74.0 fixed-CRITICAL gate and received SPDX 2.3 SBOMs.
The same artifacts were pushed to GHCR without rebuilding.

GitHub signed four image-provenance attestations, four SBOM attestations and the
manifest binding source revisions to registry digests. A separate fresh runner
verified every signature, the repository/workflow/main source identity and
exact SBOM content; it pulled only immutable digests and repeated the complete
drill without any build. Its three stages passed HTTP, browser and data checks.

The original 15 tables / 66 rows remained intact. A new-version comment produced
68 rows and survived rollback; another write under the previous version produced
70 rows. Three decisions, five idempotent operations and audit history were
preserved. HTTP 502 was detected after stopping the API. Rewritten migration
history and an unknown database head were rejected. Cleanup passed.

| Registry-side measurement | Seconds |
|---|---:|
| Update and verification | 19.340 |
| Rollback and verification | 17.066 |
| Complete imported-image drill, including setup and cleanup | 74.684 |

The published archive contains 27 files, including both drill reports, manifests,
SBOMs, signed bundles, scan results, Required CI references and checksums. Its
GitHub asset SHA-256 and every internal checksum were independently checked.
The fetched `v0.2.1` Git object is an annotated tag pointing to the source above.

Anonymous HTTPS reads of **all four final registry manifests** returned 200 and
their bytes matched the recorded digests. These packages are publicly readable
at the capture date; the workflow does not change package visibility settings.

## Boundaries and the blocked first attempt

The [first attempt](https://github.com/Oskar-Stachowski/retailops-cloud-native-platform/actions/runs/36226179735)
published images but correctly stopped before release/tag creation because the
consumer requested an unversioned SPDX predicate. [PR #43](https://github.com/Oskar-Stachowski/retailops-cloud-native-platform/pull/43)
corrected it to the signed SPDX 2.3 predicate and added a regression test. The
successful run above is the final evidence; first-attempt tags are unpromoted
diagnostic artifacts. The current suite has 13 release/promotion tests.

This release bootstraps a freshly tested predecessor from an approved source;
it does not claim reuse of a historical published release. Registry artifacts
are Linux AMD64. Separate local ARM64 tests passed build/retention/import and
SBOM generation, but do not prove a native ARM64 registry release. Runtime-image
SBOMs do not enumerate every dependency embedded in compiled browser bundles.
These small-fixture timings do not establish production RTO/RPO, arbitrary
migration reversal, production authentication or a cloud deployment.
